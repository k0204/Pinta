# 2026-08-15 工作日志

## 图层右键不再破坏多选（2026-08-15 深夜）

老板反馈：图层面板多选后，右键任意图层会把多选变成单选。

**根因**：`LayersListViewItemWidget.MenuGesture_OnPressed`（右键菜单）无条件 `doc.Layers.SetCurrentUserLayer(item.UserLayer)`，而 `SetCurrentUserLayer` 内部 = `SetSelectedUserLayers([layer])`，**清空所有选择** → 右键即单选。

**修复**（`Pinta.Gui.Widgets/Widgets/Layers/LayersListViewItemWidget.cs`）：
```csharp
if (!doc.Layers.SelectedUserLayers.Contains (item.UserLayer))
    doc.Layers.SetCurrentUserLayer (item.UserLayer);
```
右键的图层已在多选集合中 → 保留多选（菜单动作作用于整个选择）；未选中 → 才切换为单选。

**备忘**：`DocumentLayers.Selection.cs` 里 `SetCurrentUserLayer` = 单选语义；多选只走 `SetSelectedUserLayers`。这是第二次踩"SetCurrentUserLayer 会清空选择"的坑，以后涉及多选时必须先判 `SelectedUserLayers.Contains`。

## Mover 工具：Shift + 拖拽手柄等比缩放（2026-08-15 深夜）

老板需求：拖动图片改大小时按住 Shift 要能等比缩放。

**根因**：`MoveLayerTool.OnMouseDown` 里 `shift_pressed || e.IsShiftPressed` **优先**进 `StartLayerMarquee`（Shift 多选），`StartResize` 排在后面永远轮不到 → 按住 Shift 拖角手柄进的是多选框而不是缩放（RectangleHandle 的 shift 等比逻辑其实早就实现了，只是被多选截胡）。

**改动**（`Pinta.Tools/Tools/MoveLayerTool.cs`）：
1. `OnMouseDown`：`StartResize` 提到 shift 多选判断**之前** → Shift + 拖手柄 = 等比缩放；Shift + 点图层/空白 = 多选（行为不变）。
2. `UpdateCursor`：Shift 按住时若鼠标在手柄上，优先显示 resize 光标（原逻辑 shift 一律显示 marquee 光标，会误导）。
3. `StatusBarText` 加一行 "Hold Shift while dragging a transform handle to resize proportionally."（新翻译字符串）。

**等比语义**：`RectangleHandle` 的 `drag_aspect_ratio` 在 `BeginDrag` 时锁定为**拖动开始时的图层宽高比**（`PreserveAspectRatio=true`），Shift 拖动时保持该比例；中途松/按 Shift 实时切换自由/等比。

**备忘**：Mover 的变换手柄 = `transform_handle`（RectangleHandle, PreserveAspectRatio=true）；矩形选区工具 SelectTool 的 shift 等比一直可用，无需改。

## Ctrl+滚轮缩放修复（以鼠标为中心 + 连续可调比例）

老板反馈两个问题：1) Ctrl+滚轮缩放不是以鼠标位置为中心，整个画布漂移；2) 缩放比例固定档位不可调。

### 改动
1. `Pinta.Core/Classes/DocumentWorkspace.cs`：
   - **坐标系修正**：`ZoomAndRecenterView`/`ZoomAroundCenter` 原来把 center_point 当"内容坐标"直接用（`scroll_offset = center.X - adjustment.Value`），但实际传入的是 **canvas widget 坐标**，画布居中（ViewSize<PageSize）或有 canvas_offset 时两者差一个偏移 → 缩放中心漂移、画布跳走。新增 `GetCanvasPositionInContainer`（与 PositionCanvas 同逻辑）+ `PrepareRecenter`/`ApplyRecenter`，统一按 canvas widget 坐标 + canvas 容器内偏移换算。
   - 新增**连续缩放**：`ZoomByFactorAroundViewPoint(factor, viewPoint)`（写 ComboBox 文本 + UpdateCanvasScale，不再跳预设档位，5%~3600% clamp）+ `ZoomByFactorAroundViewportPoint(factor, vx, vy)`（视口坐标→canvas widget 坐标）。
   - Ctrl+滚轮、Ctrl+触控板两指缩放从档位跳变改为连续 ×factor。
2. `Pinta.Gui.Widgets/Widgets/Canvas/CanvasWindow.cs`：`HandleScrollEvent` 不再用缓存的 `current_canvas_pos`，改用 `controller.GetCurrentEvent() is Gdk.Event e && e.GetPosition(out x, out y)` 取**事件指针的视口坐标**（scroll 信号本身只有 dx/dy），失败才回退 current_canvas_pos。
3. 缩放步进可调：`ViewActions` 加 `ZoomStep` stateful SimpleAction + View 菜单「Zoom Step」radio 子菜单（10/15/20/25/33/50%）；`SettingNames.ZOOM_STEP`（Pinta.Core + Pinta 两份）；MainWindow 加载/保存；`ViewActions.ZoomStepPercent` 供 CanvasWindow 读（默认 25% → ×1.25/格）。

### 备忘
- Gdk.Event.GetPosition(out double, out double) 在 GirCore 绑定中确认存在（gdk_event_get_position）。
- 新增翻译字符串：「Zoom Step」（" {0}%" 已存在，复用）。
- 中心点数学要点：viewport 坐标 → canvas widget 坐标 = v + adjustment.Value - canvas容器内偏移；ApplyRecenter 缩放后先 PositionCanvas() 再取新偏移，才能算准 adjustment.Value。

## 动画图层禁用「调整图层大小」

老板决定：动画图层不支持缩放（缩小/放大都不做），直接限制。

### 改动
1. `Pinta.Core/Actions/LayerActions.cs`：`currentResizable` 不再包含 `AnimationOutputLayer`（原为 `currentEditable || ... is AnimationOutputLayer`），改为 `currentResizable = currentEditable` → 「Resize Layer...」菜单对动画图层置灰。
2. `Pinta/Actions/Layers/ResizeLayerAction.cs`：`Activated` 开头加防御，`layer is AnimationOutputLayer` 直接 return；`canvasSize` 简化为 `doc.ImageSize`（动画分支不可达，保留未删）。

### 说明
- 动画图层自身有 CanvasWidth/Height + 帧 Transform 几何，Resize 缩小时需同步画布尺寸/帧位置/Transform（上一轮改过 `AnimationOutputLayer.Resize` + `UpdateTransforms`），老板认为直接禁用更省心。
- 组图层本来就不在 currentResizable 里（IsEditable=false），行为不变。
- `ResizeAnimationLayer`/`ResizeSpriteSheetLayer` 等动画分支现为死代码，保留待以后恢复。
